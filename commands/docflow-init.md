You are setting up a **docflow** knowledge base in this repository.

## Steps

1. **Run doctor first** (read-only):
   ```bash
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/docflow-doctor.sh" --target "$CLAUDE_PROJECT_DIR"
   ```

2. **Route by doctor recommendation.**
   - If it recommends `/docflow-adopt`, stop and tell the user to run `/docflow-adopt` to preserve existing docs.
   - If it recommends `/docflow-repair`, stop and tell the user to run `/docflow-repair`.
   - Continue only when it recommends `/docflow-init`.

3. **Pick the docs root.** Default `docs/`. If unsure, ask the user once.

4. **Run the scaffold** (idempotent for user-authored content; generated files such as `INDEX.md` are regenerated by design):
   ```bash
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/scaffold.sh" --docs-root <DOCS_ROOT> --project "<PROJECT NAME>" --target "$CLAUDE_PROJECT_DIR"
   ```
   This creates the category tree (`product-spec/ specs/ references/ decisions/ plans/{upcoming,features,hygiene}/ reviews/{bugs}/ changelog/`), drops the templates, writes `docflow.json` at the repo root so the SessionStart hook knows where the docs live, and scaffolds `AGENTS.md` plus optional multi-agent stubs (`GEMINI.md`, `.cursorrules`) pointing at the same docs system.

5. **Wire it into the repo README.** Add a `## Documentation` section to the root `README.md` linking to `<DOCS_ROOT>/README.md` (so docs are browsable on GitHub without Claude Code).

6. **Seed the first changelog.** Create `<DOCS_ROOT>/changelog/(mmm-yy).md` for the current month from the template, summarizing recent git history (`git log --no-merges --pretty='%h %ad %s' --date=short -20`). Group commits into themes. Use the `docs-changelog` skill for the format.

7. **Map.** The scaffold auto-generates `<DOCS_ROOT>/INDEX.md` (compact `path — purpose` tree). Re-run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/docflow-map.sh" "$CLAUDE_PROJECT_DIR/<DOCS_ROOT>"` after adding/renaming docs — this is the one file an agent reads to know the whole tree without scanning it.

8. **Report** what was created and point the user at the `docs-author` (writing), `docs-router` (reading), and `docs-repair` (maintenance) skills.

## Rules
- Do not rewrite existing user-authored docs; scaffold skips existing content files, while generated files may be refreshed.
- If the repo already has docs, prefer `/docflow-adopt` over `/docflow-init`.
- Keep the docs root config in `docflow.json` accurate; the auto-context hook depends on it.
- Keep `AGENTS.md` aligned with `docflow.json`; Codex and other agents depend on that root guidance.
- Follow the naming rules in `<DOCS_ROOT>/NAMING.md` for every file you create after.
